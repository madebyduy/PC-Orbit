# v0.1 UX one-pager and hallway test (spec step 6b)

This is the page spec step 6b requires **before any UI code is written**. It fixes the seven
screens of v0.1, the exact copy they carry, and the test that decides whether they work. The
clickable/printable mockup that accompanies it is published as a design canvas (see the session
notes / artifact link); every screen below is one artboard there.

The engine behind every screen already exists and is tested — nothing here promises more than
`pco scan / checkup / plan / apply / undo / resume` can verify today. That is deliberate: the
mockup is the CLI's output re-shaped, not a new product.

## The seven screens

| # | Screen | Spec | What it must get right |
|---|---|---|---|
| 1 | First-run | 21.5 | One greeting sentence, read-only scan with progress by group (hardware → Windows → firmware → devices), then Checkup — never an empty dashboard. Exactly two questions: confirm language (guessed from locale), background drift monitoring (**default off**). No account, no telemetry question. |
| 2 | "Máy bạn đang ổn" | 21.5·4 | The nothing-to-do state is a designed result: 3–4 lines of what was read, the machine's support tier (18.4), when it was last checked. |
| 3 | Simple Overview | 21.4 | Machine header · findings · "Chuẩn bị máy cho…" outcomes · **Vừa thay đổi / Hoàn tác** panel (21.9) · one doorway to Advanced. Nothing else. |
| 4 | Checkup card | 21.6 | The four lines: what · what you gain · why it is safe · what it costs. Buttons: Sửa ngay / Thêm vào danh sách / Vì sao? / Chi tiết kỹ thuật ▸. |
| 5 | Change Basket | 21.7, step 6 | Cost header before any Apply button: n changes · restarts · minutes · steps you do yourself · what cannot be undone ▸. Each step: before → after, why it exists, mode/risk/reversible/restart, its own execution state. BitLocker gate (10.3) blocks, visibly. Three apply buttons: now / at a chosen time / I'll restart myself. |
| 6 | Guided BIOS | 8.3.3, 8.3.4 | Before restart: full instructions for *this* board (menu path, entry key, save key), QR to an offline phone page, preflight checklist. After boot: the app **reads the real value** — it never asks "did you turn it on?". The failure branch offers the five 8.3.4 answers; none ends in a bare `Failed`. |
| 7 | Result + Undo | 9.4, 21.9 | Exact counts (completed / failed / pending), never one "Done". Undo panel on the Overview: each entry has Hoàn tác or "hướng dẫn tắt ▸" for by-hand changes — the button is never hidden. |

A phone-sized artboard mirrors the BIOS instructions (the QR target), because question 4 below is
answered on a phone, not on the PC being restarted.

## Copy rules

- All user-facing copy comes from the shipped string catalogs (`data/i18n/en.json`, `vi.json`) or
  is added there first — the mockup must not invent strings the product cannot show.
- VI is the primary mockup language; screens 3 and 4 also exist in EN for the English tester.
- Findings follow 21.6's four lines exactly; written by a native speaker, never machine-translated
  from a setting name.

## The hallway test

Run with **3–5 people who are not developers**, at least one Vietnamese-speaking and one
English-speaking (spec 6b). Print the artboards or show them full-screen; the moderator plays the
computer (changes screens when the participant "clicks").

Script: *"Bạn vừa cài app này vì Docker không chạy / máy có vẻ chậm. Đây là màn hình đầu tiên.
Bạn làm gì tiếp?"* — then stay silent. Note where they hesitate, what they misread, which words
they skip.

The four questions each session must answer (spec 6b):

1. **Do they understand what their machine needs?** After screen 3–4, ask them to say it back in
   their own words. Pass: they name the outcome ("máy chưa sẵn sàng cho Docker, thiếu 3 bước"),
   not the toggle names.
2. **Do they dare press Apply?** On screen 5, watch — do not prompt. Pass: they press it, and can
   say what it will cost them (two restarts, ~9 minutes, one step by hand — the numbers the
   basket's cost header states). Fail signals: asking
   "cái này có làm hỏng máy không?", scrolling for an exit.
3. **Do they know how to undo?** After screen 7, ask "giả sử sau đó game bị giật — bạn làm gì?"
   Pass: they find Hoàn tác on the Overview unaided.
4. **Can they do the BIOS step with only their phone?** Hand them the phone artboard, take the
   "PC" away. Pass: they can state the entry key, the menu path, the setting name, and how to
   save — before "restarting".

Log per participant: language, tech comfort (1–5), time on each screen, verbatim confusion, and
pass/fail per question. Two failures on the same question across participants = that screen is
redesigned before any UI code (that is the point of testing now).

## Out of scope for the mockup

Advanced mode's 21-module navigation (only the doorway exists), Desired State, Timeline UI,
Blueprint, dark mode. All later phases; the mockup shows Simple only, matching v0.1.
